# LiliaCode Tauri / Native Preview 功能等价矩阵

本矩阵是 NanaUI 版接替正式 LiliaCode 前的可执行验收清单，不是实施完成声明。
事实源与 Tauri 证据来自 2026-08-09 的当前工作树；每个 Native 状态只按已连接的
产品行为判定，类型、事件枚举或可见占位不算实现。

## 状态与执行规则

- `BLOCKED`：尚不具备切换资格；括号内可记录已完成的子集，但不能据此降级门禁。
- “自动化门禁”必须使用同一份用例数据和预期产品结果；Tauri 通过
  `window.__liliaAgentDebug` / `tauri-driver` 执行；Native 开发态协议已建立，
  Windows GPU 启动/截图以本次验证结果为准。
- 自动化通过不取代 Windows 11 手工门禁；手工项要记录 OS build、GPU/驱动、
  DPI、输入法、构建 revision、截图/录屏与结果。
- 任一 P0/P1 行仍为 `BLOCKED`，或只有一套 UI 运行了用例，Native Preview 就不得
  接替正式名称、安装器或 `liliacode` CLI。

## P0 同语料门禁

`yarn verify:ui-equivalence:p0` 使用版本化 `tests/equivalence/p0-v1.json`，通过
`lilia-desktop-application` 类型化 API 分别写入两个全新、隔离的 home，不复制数据库、不读取用户数据。
脚本顺序启动真实 Tauri/WebDriver 与 Native/WGPU 宿主，通过稳定目标打开同一项目、根任务和三条固定时间线，
输入同一份 59 字节 Composer 草稿，从两套 UI 清除同一 Goal、删除同一 Todo，并完成 Roadmap 关联、项目
Memory、Memory 设置和 Automation 草稿/发布/启用。两端都从同一个开发态 `DesktopApplication` 快照入口导出
严格按 fixture 前缀过滤、排序且不含正文、随机 ID、时间或绝对路径的产品事实；Goal 目标、Todo 正文、Memory
正文和 Automation config 只比较字节数或 SHA-256。

`equivalence-p0-2026-08-10T22-25-29-198Z` 已证明两端 schema v4 的项目、任务、绑定会话、时间线、Composer、
Goal、Todo、Roadmap/link、Memory、Memory 全局/基线设置，以及单 Trigger Automation 的名称、scope、config、
发布和启用状态在初始/最终快照中完全一致。Tauri 验证窗口固定为 1600×1000，确保 Automation Inspector 是可见
交互而非零尺寸 DOM。当前桌面处于 Windows 锁屏，Native 截图像素门禁以 `576 non-black / 0 neutral` 明确阻断；因此这是可信的
业务等价证据，不是同轮 GPU 视觉通过证据。解锁桌面后必须重跑到 status=`passed`，不能用锁屏 PNG 或历史 Native
截图补签本轮。

当前同语料已扩展到 schema v7。`equivalence-p0-2026-08-11T13-13-12-441Z` 在上述事实之外继续覆盖 MCP、
Skill 和 Hook；Tauri 与 Native 从真实设置 UI 停用同一用户 Hook 后，最终 revision、enabled、handler identity、
event/matcher 和 secret-free 配置 SHA-256 完全一致，初始/最终 authority snapshot 与 `businessEquivalence` 均通过。
该轮 Native capture 的 576 个非黑样本中 575 个为中性色，因此只作为业务等价与采集路径证据，不据此签署视觉等价。

`2026-08-10T19-13-49-665Z` 的 Tauri Agent Debug 又从新建会话完成真实任务/会话提升、Composer 草稿与状态持久化，
并使 `chat_send_message` 成功进入共享后端；运行随后因本机未配置模型 Provider 凭据而明确记为 `blocked`。这份产物
证明首次发送路径已接通，但不能替代 Provider 就绪后的完整 Agent 场景或 Native 同轮 GPU 视觉门禁。
